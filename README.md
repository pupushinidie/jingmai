# 晶脉（暂名）

2–4 人同时行动的矿洞挖宝桌游，网页联机版。规则来自《晶脉（暂名）规则书 v0.1》。

当前是 **v0.1 测试版**：三层地图"平整"（全是通道，只有宝石格是岩壁），宝石位置随机，还没有契约系统。

## 本地运行

```bash
npm install
npm run dev          # 服务端 :3004，网页 :5177
npm test             # 规则引擎 + 服务端测试
npm run typecheck
```

一个人测试时，直接在等候房间点「加人机」；也可以建一个 2 人房，再运行 `node scripts/test-bot.mjs <房间码>`，让陪玩机器人加入。测人机和托管时用 `TURN_MS=1500 BOT_DELAY_SCALE=0.3 npm run dev`（每回合 1.5 秒、人机停顿缩短）。

## 目录

| 路径 | 内容 |
|---|---|
| `packages/game/src/data.ts` | 所有数值：层、宝石、工具、订单、参数。**调参只改这里** |
| `packages/game/src/mapgen.ts` | 随机地图生成（同一种子生成同一张图） |
| `packages/game/src/movement.ts` | 背包、移动力、寻路、跨层通路 |
| `packages/game/src/engine.ts` | 开局、规划指令、六步结算、计分、视图隐藏 |
| `apps/server` | Socket.IO 房间、断线重连、回合计时、语音信令（沿用宝石商人） |
| `apps/web` | React 界面；`MineMap.tsx` 画六边形地图，`GameBoard.tsx` 是对局界面（整屏地图 + 格子菜单 + 底部面板按钮） |

## v0.1 做了什么

- **地图**：浅脉 / 回廊 / 晶心，半径 8 / 5 / 3，宝石 18 / 12 / 6 颗，越往下越值钱。每层之间有 2 部梯子和 1 个洞口，中央是电梯。
  - 第一层每个扇区固定放 2 颗青砂玉和 1 颗赤铁晶，并检查从 6 个井口出发 8 格内可挖的宝石总价值相差不超过 20%。
  - 宝石之间互不相邻，不会围出死路；中心电梯一圈、井口、梯子和洞口所在格都不放宝石。
- **规则**：同时规划、六步结算；移动力与背包；8 种工具；8 种宝石及其特性（衰减、生长、坚硬、重型、诅咒、共鸣）；炸药；切割；交接；电梯；梯子和洞口；营地往返（存入、卖出、买工具、下井、留守、收工）；震动与分层塌方；私人订单和公共订单；平局判定。
- **操作都在地图上**：点格子会在旁边弹出这一格能做的事——走到这里、用哪件工具挖、捡起、切割、交接、撤离；在营地时井口会亮起来，点它选择下井。背包、商店、契约、订单、队伍、消息、聊天收进底部按钮，点开是浮在地图上的面板；底部同时显示本回合的计划和「确认行动」。手机上格子菜单和面板改成贴底的抽屉。
- **地图视图**：地图上方可以切换"平面 / 立体"，两种视图都能缩放（滚轮、触控板或双指捏合，左下角也有按钮），「◎ 我」会切到自己所在的层并放大居中。
  - 平面：一次看一层，放大后拖动平移；拖动不会被当成点格子（`FlatMap.tsx`）。
  - 立体：三层按同一比例叠放，电梯井、梯子、洞口画成连接上下层的竖柱。选中的层清晰、可以直接点格子行动，其他层半透明并虚化；点其他层或它旁边的名牌就切换过去。拖动旋转，右键或 Shift 拖动平移（`Mine3D.tsx`）。
  - 立体视图的点击不交给浏览器判定（浏览器会把点击给最靠前的层），而是从点击位置投射线、算出它穿过每层的哪一格（`mapGeometry.ts`，有单元测试）。
- **联机**：房间码、断线后用原昵称回到原座位、语音、聊天、再来一局。别人的私人订单和本回合行动对你不可见；地图种子要等对局结束才发（用它能重算出每人抽到的订单），交接设置只让被接收的人看到。

## 人机和托管

全站统一的做法（覆盖规则书里的超时写法）：

- **一个人也能开局**：房主在等候房间的空座位上点「加人机」，人机依次叫咕噜一号 / 二号 / 三号，带「人机」标签，「移出」请走。只有一个难度「普通」。
- **超时**：整回合限时照旧（房主选 45 秒 / 90 秒 / 3 分钟）。时间到还没确认的人：已经选好行动的按选好的结算，没选的这一回合**由人机代打**（准备阶段替他留订单、配工具；营地里替他存入、补货、选井口）。
- **托管**：连续 2 次超时转托管，人机每回合替他下完；他自己点任何操作或点「取消托管」就收回。新的一局托管清零。
- **离线**：离线的人先等 3 秒，再由人机代打（不算超时）；用原昵称加房间码回来，座位交还给他。
- 「只剩最后一人时最多再等 60 秒」只在桌上还有别的真人时生效；一个人和人机玩时人机先确认，不会缩短你的时间。
- 房间里只剩人机就关掉；人机总是同意再来一局；首页在线人数不算人机。

人机策略在 `packages/game/src/bot.ts`：`botPlan(视图, 座位)` 返回这一回合的全部指令（营地里的存入 / 卖出 / 购买 + 计划）和一句理由，`botCommand` 是一次一条的版本。只吃 `redactGameForViewer` 之后的视图（单测断言了对手的私人订单、计划、种子不同时决定完全一样）。打法：留下好凑的两张订单，带钻 + 凿 + 绳索下井，每回合挑「（价值 + 订单加成）÷ 回合数」最高、来得及挖完又来得及撤回的宝石；塌方快到、背包满了就回营地，时间不够就收工。不碰共鸣晶（一个人挖不动）。

```bash
npx tsx sim/sim-jingmai.ts --games 300   # 自对弈 2/3/4 人各 300 局（合法性、回合上限、耗时）+ 对随机 / 稳健矿工 / 其他策略的胜率
npx tsx sim/tune-normal.ts               # 换几套参数比较
```

## 新手教程

站内统一做法（剧本局 + 练习提示 + 小贴士，向导咕噜嘎），参考实现是欲罢不能，做法见 `~/projects/pipeline/handbook/tutorial-notes.md`。

- **入口**：首页简介下面的邀请卡（学过以后只剩「再看一遍」小按钮），等候房间里也有（不离开房间，房主一开局自动回牌桌）；地址带 `?tutorial` 直接打开。
- **剧本** `packages/game/src/tutorial.ts`：固定地图（种子 1），对手咕噜一号交给人机 `botPlan`（人机没有随机，局面每次一样）。晶脉是同时行动，对手总在回合一开始就规划好并确认，玩家一确认就结算。26 步：目标 → 同时行动 → 订单 → 买工具 → 移动 → 确认 → 挖掘（两回合出土）→ 背包 → 塌方 → 回井口撤离 → 存入计分 → 分数构成和订单 → 三层越深越值钱 → 平面 / 立体视图 → 再下井 → 收工和结束条件 → 托管。走完接着和咕噜一号把这局打完（练习局），结算框里有「再练一局」。
- **网页**：`apps/web/src/tutorial/` 是全站共用的教练层（逻辑从欲罢不能原样复制），`tutorial.css` 改成了晶脉的纸面风格（不是像素风）。`TutorialMode.tsx` 拼本地假房间，`tutorialGame.ts` 写「提示」的说法和小贴士。高亮锚点是 `data-tutorial`：`cell:<格子>`（格子菜单打开后改成高亮 `cell-menu`）、`confirm`、`retire`、`buy:<工具>`、`deposit:<宝石>`、`panel:orders`、`dock:<面板>`、`turn`、`collapse`、`layers`、`view-switch`、`hint`。
- **提示**：只有自己和人机时（练习局，或一个人加人机开的房间）计划栏里有「提示」（键盘 H），就是人机从你的位置算这一回合，告诉你第一步做什么和理由。
- **小贴士**：真实对局里第一次回营地、第一次到下层、第一次塌方预警、第一次宝石碎裂、收工时各出一次（`gm-tips-jingmai`，全站「不再显示小贴士」）。
- 走查脚本：`node ~/projects/qa-reports/tools/tut-jingmai.mjs <输出目录> flow|skip|waiting|room [1440|1920|1024|390] [night|day] [flat|3d]`。

## 机器人与模拟

`sim/` 里是平衡验证用的机器人：直接调用规则引擎（不走网络），每个机器人只看自己能看到的视图。

| 策略 | 打法 |
|---|---|
| 稳健矿工 Prospector | 只挖浅脉，镐 + 钻，装满就回 |
| 深潜者 Diver | 钻 + 凿 + 绳索，直奔深层高价宝石 |
| 订单猎人 Collector | 按订单配工具、挑宝石，尽快存入抢公共订单 |
| 爆破手 Blaster | 炸药炸硬宝石，卖便宜宝石补炸药 |
| 搭便车 Leech | 专挑别人挖到一半的宝石补一下，让它碎裂分成 |
| 冒险家 Gambler | 和深潜者同样装备，但安全余量为 0，留到最后才撤 |
| 随机 Random | 基准线 |
| 人机普通 Normal | 线上房间里的人机（`packages/game/src/bot.ts`），深潜者的装备 + 订单加成 |

```bash
npm run sim                              # 约 5 分钟跑 4800 局，结果写到 sim/out/（summary.json、games.jsonl）
node sim/build-report.mjs                # 生成可视化报告 sim/out/report.html
npx tsx sim/demo.ts 22 diver leech       # 在终端里逐回合看一局（种子 + 策略）
npx tsx sim/balance.ts proposal2 --games 2000 --table solo   # 试一套规则调整（方案见 sim/variants.ts）
```

`sim/variants.ts` 里是测过的规则调整方案。红区大震（tremor / quake）和共鸣契约（pact）目前只在模拟器里实现，游戏本身还没有。

改 `packages/game/src/data.ts` 里的数值后重跑，就能比较规则调整前后的结果。

## 还没做

- 契约系统和签约窗口。现在多人出力的宝石出土时直接碎裂，按贡献分 60%；「契约」按钮目前只是说明和正在开采的宝石列表。
  - 因此共鸣晶（唯一的金色宝石）只能拿碎裂分，需要金色宝石的私人订单和公共订单暂时不发（`engine.ts` 的 `obtainableGems`，加入契约后去掉）。
- 手工小区块拼接的地图骨架（v0.1 是平整地图）。
- 2 人局专属规则。

## 规则书没写清楚、v0.1 先这样处理的地方

| # | 问题 | v0.1 的做法 |
|---|---|---|
| 1 | 挖掘进度溢出（剩 1 点却用钻 +2 或炸药 +4）时，贡献怎么算 | 按实际加的进度算，不截断 |
| 2 | "满载"的定义 | 背包 0 空格 |
| 3 | 同一回合先走到电梯格、再随电梯换层 | 允许（第 2 步移动，第 5 步电梯） |
| 4 | 电梯停在某层时那层塌方 | 电梯退到上一层，方向向上 |
| 5 | 多人同时挂机 | 整回合限时（房主可选 45 秒 / 90 秒 / 3 分钟），只剩最后一位真人时最多再等 60 秒。超时没确认的人按已经选好的行动结算，没选的由人机代打这一回合；连续 2 次超时转托管（见「人机和托管」） |
| 6 | 背包里有多颗诅咒宝石 | 每颗没被封印盒压住的诅咒宝石都让移动力 −2，最低 1 |
| 7 | 最后一回合正在撤离的人 | 先到达营地、再判定矿洞塌毁，所以背包里的宝石能保住 |
| 8 | 切割、炸药之后的价值 | 向下取整 |
| 9 | 2 人局 | 照常可以开，没有额外规则 |
| 10 | 第三层宝石之间的间距 | 晶心太小，价值 10 以上的宝石之间只要求互不相邻（其他层要求隔 3 格） |

## 服务器上的启动方式

pm2 按仓库根目录的 `ecosystem.config.cjs` 直接启动一个 `node --import tsx` 进程跑服务端（不经过 `npm start`），每个游戏省下约 50 MB 内存（实测，原来被几层包装进程占掉的部分）。端口和密钥存在 pm2 里，不进仓库；`deploy.sh` 照旧 `pm2 restart`。改了 `ecosystem.config.cjs` 之后，要在服务器上带着原来的环境变量 `pm2 delete` 再 `pm2 start ecosystem.config.cjs` 一次。
